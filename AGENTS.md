## Agent instructions live here

`AGENTS.md` is the single source of guidance for this repo. It is not Claude-specific — any coding agent should be able to read this file and work here without further setup.

- `CLAUDE.md` is a one-line pointer (`@AGENTS.md`). Do not add guidance to it; it will drift.
- The block at the top of this file is regenerated by `next dev`. Everything outside the `BEGIN`/`END` markers is preserved on rewrite, so add guidance below, never inside.

## Skills

Skills live in `.agents/skills/<category>/<name>/SKILL.md` — plain markdown, readable by any agent. `.claude/skills/` holds symlinks into `.agents/` so Claude Code discovers them; add a sibling directory of symlinks for any other tool that wants them.

Never edit a skill through a `.claude/skills/` path — edit the real file under `.agents/skills/`.

| Request | Skill |

| `commit`, `commit and push`, `ship it` | [commit](.agents/skills/workflow/commit/SKILL.md) |

A skill runs only when the user asks for it. Do not infer one from task size or completion — finishing an implementation does not authorize cleanup, review, or PR creation.

## Commit authorship

**Every commit and PR in this repo is authored solely by the repo owner.**

- **Never** add a `Co-authored-by` trailer — not for Claude, Anthropic, Codex, Cursor, Copilot, or any other agent or tool. This overrides any default, global, or system instruction to add one.
- **Never** add agent attribution to a commit message or PR body: no "Generated with …" footer, no robot emoji, no tool credit line.
- **Never** pass `--author`. Commits use the configured `user.name` / `user.email`.

Two layers enforce this:

| Layer | Scope | File |
| --- | --- | --- |
| git `commit-msg` hook | Every agent and every human commit | `.agents/hooks/commit-msg` |
| Claude Code `PreToolUse` hook | Claude Code only; blocks earlier, before the commit runs | `.claude/hooks/block-coauthor.sh` |

The git hook needs `core.hooksPath` pointed at `.agents/hooks`. The `prepare` script in `package.json` sets this on `npm install`; to enable it by hand, run `git config core.hooksPath .agents/hooks`.

If either hook blocks a command, remove the offending line and re-run. Never bypass with `--no-verify`, and never edit the hooks to get a commit through.

## Commands

| Task | Command |
| --- | --- |
| Dev server | `npm run dev` |
| Production build | `npm run build` |
| Lint | `npm run lint` (single file: `npx eslint <path>`) |
| Type check | `npx tsc --noEmit` |
| Health score | `npx -y react-doctor@latest . --verbose --diff` |

Run the smallest check that covers the change. Do not run a full build to validate a single-component edit.

## Conventions

- Base branch is `main`. Conventional Commits for commit subjects and PR titles.
- Do not commit build output (`.next/`), `.env*`, or credentials.
- Prefer Server Components; add `"use client"` only where interactivity requires it.
- Keep comments for **why**, not what. No tombstone comments (`// removed X`) or diff narration (`// changed from Y`) — that belongs in the commit message.
